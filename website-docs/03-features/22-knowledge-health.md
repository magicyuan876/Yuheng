# 知识健康

知识库用久了，同一份内容往往存了好几遍：制度改版后旧版没删，同一份材料从网盘、飞书、手工上传各进来一次，在线文档里复制出来的页面又同步进了知识库。检索时这些副本互相挤占名额，回答里引用的可能恰好是过时的那一份。

知识健康在内容变化时自动检查知识库，把发现的问题列出来，由人决定怎么处理。目前检测的是**同一知识库内的重复文档**。

## 1. 检测什么

### 1.1 重复文档

两篇文档的段落在语义向量上几乎一致，就判定它们互为重复。检测只比较**索引时已经存好的向量**，不重新做 embedding，也不调用大模型，所以几乎没有额外成本。

具体做法：

1. 取出发生变化的文档的每个文本分块，在同一知识库、其它文档的分块里找最相近的若干个（按余弦相似度，同一向量维度内比较）；
2. 相似度达到阈值（默认 0.95）的分块对，按对方文档归组；
3. 对每个找到的对方文档，再从它那一侧反查一遍，合并两个方向的结果——这样无论哪篇文档触发检测，得到的结论都一样；
4. 每一对文档生成**一条**问题记录。

不参与比较的内容：

- 已停用的分块，以及摘要、OCR、图片描述等非正文分块；
- 很短的段落（少于 40 个字符）。标题、页脚、「联系我们」这类模板内容在不相关的文档之间也高度相似，计入会让同一模板生成的文档全部被判为重复；
- 自动生成的问题（它们也有向量，但不是文档的段落）。

### 1.2 一条问题记录里有什么

| 字段 | 含义 |
| --- | --- |
| 主体文档 / 相关文档 | 主体是「更大比例被对方包含」的那一篇，也就是更值得考虑删掉或合并的那一篇 |
| 重叠比例 `overlap_ratio` | 主体文档的段落中，有多少比例在对方文档里找到了几乎相同的段落 |
| 相似度 `score` | 最相近的一对段落的相似度 |
| 严重程度 | 重叠比例 ≥ 50% 为 **warning**（主体基本是副本），否则为 **info**（只有部分段落相同） |
| 证据 | 最多 3 对最相近的段落，各截取前 300 字 |

### 1.3 暂不检测的内容

目前**不做**以下检测：

- **内容矛盾**：两篇文档对同一件事说法不一致（比如新旧两版制度的报销时限不同）。这需要大模型逐对阅读，暂未提供；
- **跨知识库**的重复；
- 文档过期、链接失效等。

FAQ 类型的知识库不参与检测：FAQ 在导入和编辑时已经按标准问去重（见 [FAQ 能力](17-faq.md)）。只开了关键词检索、没开向量检索的知识库没有向量可比，同样不检测。

## 2. 什么时候检测

文档**索引完成后约 30 秒**自动检测一次。上传、重新解析、手工编辑、在线文档页面同步到知识库，最后都经过同一个索引后处理步骤，所以都会触发。

同一篇文档短时间内连续变化（例如在线文档边写边保存、批量重新解析），落在同一个 30 秒窗口内的变化只检测一次；检测进行中又发生的变化会安排新的一次，不会漏掉。检测作为后台维护任务执行，失败会按队列的重试策略重试；没有 Redis 的单进程部署同样可用。

也可以在知识库的健康页面点「重新检测」，为库里所有已完成索引的文档各安排一次（单次最多 5000 篇，分批错开执行）。只有知识库的创建者或管理员可以发起，共享给其他空间的知识库只能由所属空间发起。

问题记录会跟着文档走：文档被删除或移动到其它知识库，与它有关的问题记录随之删除。

## 3. 怎么处理

每条问题有三种状态：

| 状态 | 含义 |
| --- | --- |
| `open` 待处理 | 新发现、还没人处理 |
| `dismissed` 已忽略 | 有人看过，决定保留两篇文档（比如一篇是另一篇的节选，有意为之） |
| `resolved` 已解决 | 检测不再报告它——内容已经改了或删了 |

常见的处理方式：

- **删掉或合并副本**：删除主体文档，或者把两篇合成一篇。下次检测时问题自动变为「已解决」，不需要手工关闭；
- **忽略**：两篇都要保留时点「忽略」。之后的检测只要证据不变（同样的段落仍然相同），它就一直保持忽略；某一侧的相关段落内容改了，问题会重新打开，因为你当初忽略的是那些内容，不是这两篇文档今后的样子。重新解析文档（分块 ID 变了但文字没变）不会让已忽略的问题重新打开；
- **重新打开**：误点了忽略，可以改回待处理。

忽略和重新打开会记入知识库的活动记录。

在线文档页面也能看到自己的重复问题：只展示对方同样是你有权查看的页面的那些；对方是上传的文件、你看不到的页面或其它空间的页面时，只显示「另有 N 条」，不透露对方的标题和内容。

## 4. 配置

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `YUHENG_FINDINGS_ENABLED` | `true` | 是否在索引完成后自动检测。关闭后不再产生新的问题，已有记录仍可查看 |
| `YUHENG_FINDINGS_DUPLICATE_MIN_SCORE` | `0.95` | 两个段落被视为「同一段文字」的余弦相似度，取值 0.5–1 |

阈值调低会报出更多只是话题相近的段落，调高则只剩几乎逐字相同的内容。取值超出 0.5–1 时服务拒绝启动，而不是悄悄按默认值运行——阈值写错（比如写成 `95`）不会有任何报错，只会让检测什么都报或什么都不报，很难察觉。

检测依赖检索引擎能比较已存储的向量。内置的 PostgreSQL（pgvector）引擎支持；其它引擎若不支持，健康概览里会显示「不支持」，也不会安排检测。

## 5. API

| 方法 | 路径 | 说明 | 权限 |
| --- | --- | --- | --- |
| GET | `/api/v1/knowledge-bases/:id/findings` | 问题列表。`status`=`open`（默认）/`dismissed`/`resolved`/`all`，`type`、`knowledge_id` 过滤，`page`、`page_size`（最大 100） | 知识库读权限；API Key 需 `retrieve` |
| GET | `/api/v1/knowledge-bases/:id/findings/summary` | 概览：`open_total`、`open_by_type`、`last_scan_at`、`enabled`、`supported` | 同上 |
| PATCH | `/api/v1/knowledge-bases/:id/findings/:finding_id` | `{"status":"dismissed"}` 忽略，`{"status":"open"}` 重新打开已忽略的问题 | 知识库创建者或管理员，且有编辑权限；API Key 需 `ingest` |
| POST | `/api/v1/knowledge-bases/:id/findings/scan` | 重新检测整个知识库，返回 `{"queued": n}` | 知识库创建者或管理员，限所属空间；API Key 需 `manage_kbs` |
| GET | `/api/v1/docs/pages/:pid/findings` | 在线文档页面的问题：`items`（对方是可读页面的）与 `other_count` | 页面读权限 |

列表中的每一项：

```json
{
  "id": "…",
  "knowledge_base_id": "…",
  "type": "duplicate",
  "detector": "duplicate",
  "severity": "warning",
  "status": "open",
  "score": 0.981,
  "overlap_ratio": 0.83,
  "subject": { "knowledge_id": "…", "title": "差旅报销制度（旧版）" },
  "related": { "knowledge_id": "…", "title": "差旅报销制度" },
  "evidence": [
    {
      "subject_chunk_id": "…", "subject_excerpt": "…",
      "related_chunk_id": "…", "related_excerpt": "…",
      "score": 0.981
    }
  ],
  "created_at": "…", "updated_at": "…",
  "resolved_at": null, "resolved_by": null
}
```

`resolved_by` 为忽略者的用户 ID，或 `system`（检测不再报告而自动解决）。

## 6. 局限

- 判断依据是 embedding 模型眼中的「语义相同」。改写过措辞、但意思一样的段落可能被判为重复；逐字相同但夹在大量不同内容里的段落只贡献很小的重叠比例；
- 每篇文档最多与 20 篇最相似的文档比较，超长文档只比较前 5000 个分块；
- 知识库换了 embedding 模型、旧文档尚未重新索引时，新旧维度的向量之间无法比较；
- 检测只看同一知识库内部。

检测框架本身是可扩展的：新的检测器可以通过扩展点接入，无需修改核心代码，见 [扩展点指南](../06-development/03-extension-points.md) 第 9 节。
