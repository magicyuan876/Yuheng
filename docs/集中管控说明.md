# 集中管控基础设施

面向内部部署的场景：平台运维统一配置模型、解析引擎、向量库、存储等基础设施，其他注册用户只管使用，不需要（也不应该）接触凭据。

> 与[空间 RBAC](./RBAC说明.md)、[共享空间](./共享空间说明.md)正交：RBAC 管的是「一个空间内谁能做什么」，共享空间管的是「知识库如何跨空间共享」，本文档管的是「基础设施归谁配」。

---

## 一、为什么空间角色解决不了这件事

Yuheng 的每个自助注册用户，都会自动获得一个属于自己的个人空间，并成为该空间的 **Owner**（`internal/application/service/user.go` 的 `EnsureOwner`）。角色是分级的（`TenantRole.HasPermission` 比较 `Level()`），Owner 天然满足 Admin。

所以把某个设置页的门槛从 Viewer 提到 Admin 甚至 Owner，对自助注册用户**没有任何约束力** —— 他们在自己的空间里始终是最高角色。

要表达「只有平台运维能配」，必须引入一个与空间角色正交的维度。这就是 `governance.centralized_infra`。

## 二、分层结果

| 维度 | 设置页可见项 | 可见对象 |
|---|---|---|
| **个人** | 通用偏好、用户资料 | 所有注册用户 |
| **空间** | 空间信息、成员、对话历史索引、**API Key** | 空间 Owner/Admin |
| **平台** | 模型、Ollama、向量库、解析引擎、存储、网络搜索 | **仅系统管理员** |

发布集成留在空间维度：每个团队发布自己的机器人、嵌入挂件和 API Key，那是空间业务而非共享基础设施。

**关键点：入口隐藏不影响使用。** 建知识库时的选择器走各自的 Viewer+ 只读接口，平台资源照常出现在下拉框里 —— 只是凭据和端点被 DTO 层抹掉了。

## 三、开启

`设置 → 系统 → 访问` 里打开「集中管控基础设施」，立即生效、无需重启。也可用环境变量 `YUHENG_GOVERNANCE_CENTRALIZED_INFRA=true` 作为部署期默认值（数据库里的值优先）。

**前置条件：**

1. **先有系统管理员。** `.env` 里设 `YUHENG_BOOTSTRAP_SYSTEM_ADMIN_EMAIL=<你的邮箱>` 并重启一次，该邮箱对应的账号会被提升为系统管理员（幂等，且仅在当前没有任何系统管理员时生效）。这是整个流程里唯一绕不开环境变量的一步，之后的提权/撤销都走管理页。
2. **配好 `SYSTEM_AES_KEY`。** 否则模型、存储、解析引擎的凭据在数据库 JSONB 里是明文。共享出去意味着更多人能碰到这份数据，这是前置条件而非可选项。

开关关闭时行为与升级前完全一致，可以先验证再切。

## 四、平台共享资源

集中管控回答的是「谁能配」，共享回答的是「配好的东西谁能用」。两者配合才完整：普通用户失去写权限之后，需要有平台提供的实例可选。

| 资源 | 共享方式 | 取消共享的护栏 |
|---|---|---|
| 模型 | 模型卡片菜单 → 设为平台共享 | 仍被**任意空间**的知识库绑定时拒绝 |
| MCP 服务 | 服务卡片菜单 → 设为平台共享 | 无（Agent 按调用解析工具，失效会明确报错） |
| 向量库 | 卡片菜单 → 设为平台共享 | owner 之外的空间仍有知识库绑定时拒绝 |
| 存储实例 | 卡片菜单 → 设为平台共享 | owner 之外的空间仍有默认存储 / 知识库 / 活跃资源绑定时拒绝 |
| 网络搜索 Provider | 卡片菜单 → 设为平台共享 | 无（按次选用，失效退化为「网络搜索不可用」） |
| 解析引擎 | 「平台默认」档位（见下节） | 不适用（是配置块不是实例） |

共享资源对非系统管理员**只读**：凭据从不返回，端点 / Base URL / 额外配置也一并抹掉，只保留名称、类型等「能力描述」——正好够选择器渲染。

### 为什么护栏是必要的

`knowledge_bases` 的 `embedding_model_id` / `vector_store_id` / `storage_backend_id` 都是裸字符串列，**没有外键约束**。取消共享或删除一个还在被别的空间引用的资源，那个空间的检索会**静默失效** —— 没有报错，只是查不出东西。所以这些操作在放行前都会做跨空间引用扫描。

对存储实例和网络搜索 Provider，删除要求先取消共享：删除路径上的引用检查是按空间计的，直接删会把 owner 空间清干净、却留下其他空间的悬空引用。

## 五、解析引擎的三层配置

解析引擎不是实例列表而是配置块，所以走继承而非共享：

```
部署环境变量  <  平台默认（系统管理员）  <  空间覆盖
```

- **部署环境变量**：在 DocReader 内部生效，每个引擎读自己的变量。
- **平台默认**：`设置 → 解析引擎 → 平台默认`（仅系统管理员可见）。
- **空间覆盖**：`设置 → 解析引擎 → 本空间`。集中管控开启后该入口对非系统管理员隐藏。

合并是**逐字段**的：只覆盖了 MinerU 端点的空间，仍然继承平台的天枢、PaddleOCR 等全部设置，不会因为「填了一个字段」而丢掉其余引擎。

布尔开关用指针类型正是为此 —— 空间显式关掉公式解析，会覆盖平台默认的开启；而空间从未提及的字段才落到平台默认。

## 六、运维注意

- **Embedding 模型换不得。** 更换已被知识库使用的 embedding 模型意味着已有向量全部失效，必须重建索引。UI 在切换 Embedding 模型的共享状态时会额外提示。
- **额度没有护栏。** 模型共享出去后所有空间共用同一份 API 额度。`model.max_concurrency` 限制的是并发不是配额。建议先上线观察实际用量。
- **建议收紧注册。** 内网可达但非隔离时，把 `auth.registration_mode` 设为 `invite_only`，避免陌生人注册后白嫖平台模型。
- **YAML 与 UI 的所有权。** 系统管理员一旦在 UI 里保存过某个由 `config/builtin_models.yaml` 下发的内置模型，该行 `managed_by` 会被清空，之后 YAML 不再覆盖它；反过来，UI 也拒绝删除仍由 YAML 托管的行（删了下次启动会被 reconciler 写回）。详见 [内置模型管理指南](./BUILTIN_MODELS.md)。

## 七、相关实现

| 关注点 | 位置 |
|---|---|
| 路由守卫 | `internal/middleware/rbac.go` 的 `RequirePlatformManaged`，经 `internal/router/rbac.go` 的 `g.PlatformManaged()` 挂载 |
| 开关定义 | `internal/application/service/system_setting.go` 的 registry，键 `governance.centralized_infra` |
| 前端入口表 | `frontend/src/config/settingsAccess.ts` 的 `PLATFORM_MANAGED_SETTINGS_SECTIONS` |
| 共享读路径 | 各 repository 的 `(tenant_id = ? OR is_builtin = true)` |
| 共享写守卫 | `internal/application/service/platform_shared_infra.go` |
| 解析引擎分层 | `internal/types/parser_engine_platform.go` |

改动入口规则时请同步更新前端表与后端路由 —— 两者不一致会产生「能打开但存不进去」或「界面说没有但接口还能调」的页面。
