# 在线文档（docs 模块）部署说明

在线文档默认**关闭**。打开它需要一个开关；协同编辑是另一个开关，而且是可选的。

先说清楚这两者的关系，因为它决定了你要部署几个东西：

| | 只开 docs | docs + 协同服务 |
|---|---|---|
| 空间、页面树、权限、评论、历史、标签、搜索、分享、导入导出 | ✅ | ✅ |
| 同一页面多人同时编辑 | ❌ 独占编辑 | ✅ 实时协同 |
| 需要额外容器 | 无 | collab |

**独占编辑不是降级模式。** 进入编辑即取得一个 5 分钟的租约并在打字时自动续期，
其他人只读并看到「某某正在编辑」；持有者关页面或断线满 5 分钟后租约过期，下一个
人自动接管。前后端用的是同一套编辑器、同一份构建产物，差别只在传输层。所以：
**不要把协同服务当成 docs 的前置依赖**，它是加分项。

---

## 一、Docker Compose

### 1. 只开在线文档

`.env` 里改一行：

```bash
YUHENG_DOCS_ENABLED=true
```

然后照常 `docker compose up -d`。没有新容器，`/api/v1/docs/**` 路由注册上，
前端出现「文档」入口。

### 2. 加上协同编辑

`.env` 里再加两项：

```bash
# 至少 16 个字符；两端必须一致
YUHENG_COLLAB_SHARED_SECRET=$(openssl rand -base64 32)
# 浏览器实际访问的地址。前端 nginx 已经把 /collab 代理到协同容器，
# 所以填站点自己的地址即可，不需要单独开端口。
YUHENG_COLLAB_URL=ws://localhost/collab
```

HTTPS 站点填 `wss://你的域名/collab`。**不要在 HTTPS 页面里填 `ws://`**，
浏览器会直接拒绝这个连接，而且报的是混合内容错误，跟协同服务本身无关。

启动时带上 profile：

```bash
docker compose --profile docs up -d
```

镜像需要单独构建（它不在 `make build-images` 里，因为 docs 默认关闭，
不该让每次构建都多跑一道 node 打包）：

```bash
make build-images-collab
```

### 3. 验证

```bash
# 协同服务自身 + 它到 app 的回调是否通
curl -s http://localhost:1234/healthz
# {"status":"ok","backend":"ok",...}
```

`backend` 显示 `unreachable` 说明协同服务连不上 app，检查 `COLLAB_BACKEND_URL`
和共享密钥；这种情况下容器会被 healthcheck 判为不健康，而不是带病接客。

## 二、Kubernetes（Helm）

```bash
helm install yuheng ./helm \
  --set docs.enabled=true \
  --set collab.enabled=true \
  --set secrets.collabSharedSecret="$(openssl rand -base64 32)" \
  --set ingress.enabled=true \
  --set ingress.host=docs.example.com
```

`collab.enabled` 要求 `docs.enabled`，否则 chart 直接渲染失败——与其部署一个
没东西可服务的进程，不如在 `helm template` 阶段就说清楚。

`docs.collabUrl` 默认取 `ws(s)://<ingress.host>/collab`，正好是 chart 自己那条
ingress 规则的落点。浏览器从别的入口进来时再单独设。

两件必须在 ingress controller 上确认的事，见 `helm/README.md`：WebSocket 的协议
升级要能穿过代理，以及读超时不能是默认的 60 秒——一次编辑会话会把一条连接一直
开着，按 60 秒掐会表现为「网络一直在抖」。

### 多副本

`collab.replicaCount > 1` **必须**同时 `collab.redis.enabled=true`。否则两个副本
上的同一篇文档互相看不见：两边各自都是自洽的，都以为自己是对的，最后一个落盘的
覆盖另一个。这个故障不报错，所以 Redis 地址由 chart 直接模板出来，而不是留给人记。

## 三、配置项速查

完整注释在 `.env.example` 的 K 组。这里只列最常被问到的：

| 变量 | 说明 |
|---|---|
| `YUHENG_DOCS_ENABLED` | 模块总开关 |
| `YUHENG_COLLAB_URL` | 浏览器侧 WebSocket 地址；留空即独占编辑 |
| `YUHENG_COLLAB_SHARED_SECRET` | 两端 HMAC 共享密钥，≥16 字符 |
| `YUHENG_COLLAB_INTERNAL_URL` | 本服务回调协同服务的地址，compose 里默认 `http://collab:1234` |
| `YUHENG_DOCS_MAX_YDOC_BYTES` | 单页 Yjs 状态上限；**协同服务要用同一个值**，两边不一致会出现一边收下、另一边拒绝落盘 |
| `YUHENG_DOCS_MAX_ATTACHMENT_BYTES` | 单个附件上限 |
| `YUHENG_DOCS_TRASH_RETENTION_DAYS` | 回收站保留天数，到期由清理任务真删 |
| `YUHENG_DOCS_PUBLIC_SHARING` | 是否允许把页面分享给工作空间以外的人 |

## 四、安全边界

几条写在代码里、这里复述一遍的事实：

- **协同服务不连数据库，也不持有任何凭证**，除了那把共享密钥。鉴权、取文档、
  写回文档全部是回调 app，每次调用双向签名。它被攻破，攻击面就是「能对 app
  发出签名请求」，而不是「能读整个库」。
- **前端 nginx 的 `/collab` 只透传 WebSocket。** 协同服务的内部回调接口匹配的是
  `/internal/collab/…`，经这条 location 进来一律不匹配、返回 404，所以内部接口
  只能从容器网络里直连，不会因为开了这条规则而暴露到公网。
- **导出的压缩包只属于发起人**，里面只有他当时能读的页面，且一天后由清理任务
  连同作业记录一起删除。
